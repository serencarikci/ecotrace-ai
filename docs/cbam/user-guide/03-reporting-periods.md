# 3. Reporting periods

**Previous:** [Organizations and installations](02-organizations-and-installations.md) · **Next:** [Product profiles](04-product-profiles.md)

## Purpose

A **reporting period** links one installation to one time window. Almost all CBAM data lives under that period.

## Who can use it

- View: **view** access
- Create draft, open data collection, archive: **edit** access

## What must be completed first

- At least one installation

## How to open

- List: SKDM → **Reporting Periods**
- Detail: open a period row

![Reporting periods list](assets/06-reporting-periods-list.png)

![Reporting period detail with tabs](assets/07-reporting-period-detail.png)

## Period list

| Control | Meaning |
|---------|---------|
| Reporting Period | Choose the calendar period to link |
| Add Draft Binding | Creates a draft period for the selected window |

## Period detail

The header shows installation, period dates, and status.

### Status labels (what you see)

| Status | Meaning |
|--------|---------|
| Draft | Period created; limited entry until opened |
| Data collection | Normal writable period for editors |
| Locked | You can look, but you cannot change data |
| Archived | Closed; treat as read-only history |

Editors can **Open data collection** and **Archive** when those buttons appear.

## Writable period rule

Many create and calculate buttons need **edit** access **and** a writable status (usually Draft or Data collection). Locked periods stay visible but block writes.
